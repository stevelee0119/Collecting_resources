## 1. 매일 확인할 것

### 1-1. 브리핑 메일

메일 상단 통계에서 다음을 확인합니다.

| 항목 | 의미 | 이상 징후 |
| --- | --- | --- |
| 신규 | 처음 발견한 자료 수 | 며칠 연속 0 이면 소스 장애 의심 |
| 수정 | 개정판·수정본으로 다시 확인된 자료 | — |
| P1 / P2 | 즉시 검토 가치가 높은 자료 | — |
| 수집실패 | 건너뛴 소스 수 | 1개 이상이면 아래 §3 참조 |

메일 하단 **"수집 실패·건너뛴 소스"** 섹션에 원인 코드가 표시됩니다.

### 1-2. 요약 근거수준 확인

각 카드에 표시되는 근거수준을 반드시 확인하십시오.

- `원문 전체 분석` (FULLTEXT) — 원문을 받아 분석
- `초록만 분석` (ABSTRACT) — **원문 전체를 읽은 결과가 아닙니다**
- `서지정보만 분석` (METADATA_ONLY) — 제목·키워드 기준

초록 기반 요약을 전체 논문 분석처럼 인용하지 마십시오.

### 1-3. 라이선스 경고

`⚠ 라이선스 불명확` 표시가 있는 자료는 **내부 열람용**입니다.
외부 배포·인용 전에 원 출처의 이용조건을 직접 확인하십시오.

## 2. 주기적으로 할 것

### 매주

```bash
python main.py doctor
```

- 사용 가능 소스 수가 줄지 않았는지 확인
- `99_미분류_검토필요` 폴더에 쌓인 자료를 검토하고 필요하면 주제 폴더로 이동
- `data/quarantine/` 에 격리된 파일이 있으면 원인 확인 후 삭제

### 매월 (정합성 점검 후)

```bash
python main.py run --reconcile
```

- 자동 실행되지만, 실패했다면 수동으로 재실행합니다.
- Excel 의 `오류_검토필요` 시트를 열어 반복 실패 자료를 확인합니다.

### 분기별 (PRD §3.4, §5)

1. **검색어 사전 검토**

   ```bash
   python scripts/check_search_terms.py
   ```

   - 누락·오탐 샘플을 확인하고 `config/search_terms.yaml` 을 보정합니다.
   - 수정 시 `dictionary_version` 을 올리고 `changelog` 에 변경일·변경자·사유를 남깁니다.
   - 새 용어를 추가하면 `human_verified: true` 로 검수 표시를 합니다.

2. **접근정책 재검토**

   - `config/sources.yaml` 의 `terms_checked_at`, `last_policy_review_at` 을 갱신합니다.
   - 403/429 가 반복되거나 이용약관이 바뀐 소스는 `download_policy` 를 `link_only` 로 낮춥니다.
   - 정책이 불명확하면 자동 다운로드를 중지합니다.

3. **API 가이드 갱신**

   ```bash
   python main.py api-guide --excel
   ```

### 자동수집 대상이 아닌 소스

| 소스 | 이유 |
| --- | --- |
| RISS | 공개 API 가 상호대차·E-DDS·Rinfo 통계·FRIC 용이며 학술 서지 검색 API 가 없음 |
| SSRN | 이용조건상 자동 다운로드를 하지 않고 공식 Abstract Page 만 연결 |

> 미확정 소스는 공식 문서에서 상세주소를 확인해 `endpoint` 에 넣고,
> 응답 필드명을 `field_map` 에 맞추면 코드 수정 없이 동작합니다.
> 확인 후에는 `verification_status` 를 `VERIFIED` 로 올리고
> `verified_source` · `verified_at` · `verified_method` 를 갱신하십시오.

## 3. 오류 코드별 대응

메일과 `data/metadata/dlrcis.db` 의 `errors` 테이블에 기록됩니다.

| 코드 | 의미 | 대응 |
| --- | --- | --- |
| `CREDENTIAL_MISSING` | 인증정보 미설정 | `.env` 에 해당 환경변수 추가 → [API 가이드](API_발급_연동_가이드.md) 참조 |
| `ENDPOINT_NOT_CONFIGURED` | 공식 엔드포인트 미확정 | 공식 문서 확인 후 `sources.yaml` 의 `endpoint` 입력 |
| `API_RATE_LIMIT` | 호출량 초과 | `rate_limit_rps` 를 낮춤. 키 발급으로 쿼터 상향 검토 |
| `POLICY_BLOCKED` | 정책상 다운로드 불가 | 정상 동작입니다. 링크로 보존됩니다 |
| `LOGIN_REQUIRED` / `PAYWALL` | 인증·결제 필요 | 정상 동작입니다. **우회하지 마십시오** |
| `LINK_EXPIRED` | 링크 만료·불일치 | 다음 실행에서 재조회됩니다. 반복되면 Adapter 점검 |
| `FILE_NOT_DOCUMENT` | HTML 오류페이지 등 | 소스의 다운로드 URL 구조 변경 가능성 → Adapter 점검 |
| `FILE_CORRUPTED` | 파일 손상 | 재시도 후에도 반복되면 원 출처 확인 |
| `DUPLICATE_FILE` | 동일 파일 이미 보관 | 정상 동작입니다 |
| `TEXT_EXTRACTION_FAILED` | 텍스트 추출 실패 | 스캔본이면 OCR 후보. 원문은 보존됩니다 |
| `SUMMARY_FAILED` | 요약 생성 실패 | 추출식 요약으로 자동 대체됩니다 |

### 소스가 연속 실패할 때

연속 5회 실패하면 로그에 경고가 남고 circuit breaker 가 열려 15분간 호출을 멈춥니다.

```bash
# 해당 소스만 다시 시도
python main.py run --daily --source <source_id> --log-level DEBUG
```

원인이 정책 변경이라면 `sources.yaml` 에서 `enabled: false` 로 내리고
`download_policy` 를 재검토한 뒤 다시 켭니다.

## 4. 자료 찾기

```bash
# 전문검색 (제목·초록·요약·본문)
python main.py search "위법수집증거"
python main.py search "operational law" --limit 50
```

DB 를 직접 조회할 수도 있습니다.

```bash
sqlite3 data/metadata/dlrcis.db \
  "SELECT publication_date, topic_primary, title_ko, file_path
     FROM resources
    WHERE priority_level IN ('P1','P2')
      AND publication_date >= '2026-08-01'
    ORDER BY relevance_score DESC;"
```

### 한 자료의 이력 추적 (§18.4 감사가능성)

```sql
-- 어떤 검색어로 언제 발견했고, 어떤 출처 URL 들을 가지고 있는지
SELECT r.title_ko, r.discovered_at, r.discovered_by_query,
       r.query_dictionary_version, r.summary_basis, r.license,
       m.source_id, m.url, m.url_role
  FROM resources r
  LEFT JOIN resource_source_map m ON m.resource_id = r.resource_id
 WHERE r.doi = '10.1234/example';
```

## 5. 백업

정기적으로 백업할 대상:

```text
data/metadata/dlrcis.db     # 원본 DB — 가장 중요
data/library/               # 수집한 원문 파일
data/manifests/             # 일자별 수집 이력
config/                     # 설정 (검색어 사전 포함)
.env                        # 인증정보 — 별도 안전한 곳에 보관
```

DB 는 WAL 모드이므로 백업 전 프로세스를 멈추거나 다음을 사용하십시오.

```bash
sqlite3 data/metadata/dlrcis.db ".backup 'backup/dlrcis_$(date +%y%m%d).db'"
```

## 6. 새 소스 추가하기

1. **접근정책 사전 점검** — `robots.txt`, 이용약관, 저작권정책, 자동수집 허용 여부
2. `config/sources.yaml` 에 등록

   ```yaml
   - source_id: new_source
     name: "기관명"
     connector: institution_feed     # 또는 generic_api / 전용 Adapter
     mode: [FEED]
     query_language: ko
     access_methods:
       - type: RSS
         auth_type: NONE
         credential_required: false
         endpoint: "https://example.go.kr/rss"
         verification_status: VERIFIED
     download_policy: manual_review   # 처음에는 보수적으로
     rate_limit_rps: 0.3
     terms_checked_at: "2026-08-22"
   ```

3. 확인

   ```bash
   python main.py doctor
   python main.py run --daily --source new_source --dry-run
   ```

4. 문제가 없으면 `download_policy` 를 `oa_only` 또는 `allowed` 로 올립니다.
5. 인증이 필요하면 `python main.py api-guide` 로 가이드를 갱신합니다.

전용 Adapter 가 필요하면 `src/connectors/` 에 `SourceConnector` 하위 클래스를 만들고
`src/connectors/__init__.py` 의 `CONNECTOR_REGISTRY` 에 등록합니다.
구현해야 하는 최소 메서드는 `discover()` 와 `normalize()` 입니다.

## 7. 하지 말아야 할 것 (PRD §7.3)

다음은 제품 요구사항에서 **명시적으로 제외**된 기능입니다. 구현·요청하지 마십시오.

- CAPTCHA 회피
- 로그인·기관인증 우회
- Paywall 우회
- Anti-bot 방어 회피
- 임시 토큰·세션ID 탈취 또는 재사용
- 금지된 브라우저 자동화 방식의 대량 다운로드
- 검색엔진 HTML 결과 페이지의 대량 스크래핑

접근이 막혀 있다면 그것은 **정상 동작**입니다. 링크로 보존하고 사람이 직접 열람하십시오.
