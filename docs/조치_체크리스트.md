## B. API 발급·활용신청 (기관 로그인 필요)

각 항목은 **신청 → 승인 → 키 발급 → Secret 등록** 순서입니다.
Secret 이름은 아래 표의 것을 그대로 쓰셔야 워크플로가 주입합니다.

- [ ] **B-1. 디지털집현전** → Secret `KKNOWLEDGE_API_KEY` *(신규 추가 소스)*

- [ ] **B-2. CORE** → Secret `CORE_API_KEY`

  - 효과: OA 원문 확보 경로 하나가 더 살아납니다

- [ ] **B-3. NKIS** → Secret `NKIS_API_KEY`
  - https://www.nkis.re.kr/openDesc.do — 회원가입 후 로그인 상태에서 활용신청

## C. 명세 확인 후 설정 입력이 필요한 것

> **이 항목들을 제가 채우지 못한 이유:** 해당 문서가 모두 로그인 뒤에 있거나
> (NKIS·디지털집현전·공공데이터포털 활용신청 화면), 이 실행 환경에서 해당 도메인
> 접속이 차단되어 있습니다. 추측한 주소를 넣지 않는 것이 이 프로젝트의 규칙이고,
> 테스트가 그 규칙을 강제합니다. **화면에서 값을 확인해 알려주시면 제가 반영합니다.**

| 국회입법조사처 | `apis.data.go.kr/9735000/PublicationService/getResearchReportList` | 요청변수·출력결과 표 | data.go.kr 15125970 상세페이지 |

  - 확인 방법: 키 등록 후 `python main.py doctor --probe` → 200 인데 0건이면 필드명 불일치입니다

### C-2. 주소 자체를 찾지 못한 기관형 소스

2026-08-23 에 다시 검색했지만 공식 RSS·API 주소를 확인하지 못했습니다.

- [ ] **C-2-a. 사법정책연구원(`jpri`)** — 발간자료 게시판만 있고 RSS 미확인
  - 확인: https://jpri.scourt.go.kr/post/postList.do?boardSeq=7&menuSeq=11&lang=ko 하단에 RSS 아이콘이 있는지
  - 참고: 대법원 사법정보공유포털(`openapi.scourt.go.kr`)은 **사건정보만** 제공해 발간물에는 못 씁니다
- [ ] **C-2-b. 법무연수원(`ioj`)** — 전자도서관 신착자료 RSS 여부
  - 확인: https://book.ioj.go.kr/$/10140/contents/new 페이지에 RSS 제공 여부
- [ ] **C-2-c. 한국국방연구원(`kida`)** — '공공데이터 소개' 페이지의 제공 형식
  - 확인: https://kida.re.kr/frt/contents/frtContents.do?sidx=2127&depth=3
  - 국내외 국방·안보 데이터 목록과 학술지 목록을 개방한다고 안내되어 있으나 API 목록·주소는 미확인
- [ ] **C-2-d. 국가인권위원회 발간물(`humanrights` / RSS)** — 인권도서관 RSS 여부
  - 확인: https://library.humanrights.go.kr/

> 위 네 곳은 RSS·API 가 정말 없을 수도 있습니다. 그 경우 자동수집 전에
> `robots.txt`·이용약관·저작권정책을 점검한 뒤 **허용되는 범위에서만** 전용 Adapter 를
> 구성해야 합니다 (PRD §7.3). 로그인·CAPTCHA·Paywall 우회는 하지 않습니다.

## D. 확인 완료 — 추가 조치 없음

- [x] **RISS** — 공개 API 는 상호대차·E-DDS·Rinfo 통계·FRIC 검색용이며 **학술 서지 검색 API 가 없습니다.**
      다른 소스가 찾은 RISS 링크만 보존합니다. `RISS_API_KEY` 는 등록해도 쓰이지 않습니다
- [x] **SSRN** — 이용조건상 자동 다운로드를 하지 않고 공식 Abstract Page 만 연결합니다
- [x] **ScienceON (KISTI)** — **2026-08-23 수집 대상에서 제외했습니다.**
      이용신청 때 제출한 맥주소에 인증이 묶입니다. 토큰 발급 요청은
      `{mac_address, 현재일시}` JSON 을 32자리 인증키로 AES256 암호화해 `client_id` 와
      함께 보내고, Gateway 가 복호화해 등록된 맥주소와 대조한 뒤에야 토큰을 내줍니다.
      실행마다 맥주소가 바뀌는 GitHub Actions 러너에서는 인증이 성립하지 않습니다.
      **신청 진행 중이셨다면 중단하셔도 됩니다.**
      되살리려면 ① 고정 맥주소 서버로 이용신청 ② 토큰 발급 절차 구현
      ③ `sources.yaml` 의 `enabled: true` 세 가지가 모두 필요합니다
- [x] **한국형사·법무정책연구원 Open API** — 공공데이터포털의 KICJ 데이터셋 2건
      (15140051 교정통계연보 / 15140052 범죄예방정책)은 **모두 통계**라 연구보고서 수집에는
      쓸 수 없습니다. 연구보고서는 기관 발간물 게시판에 있으며, NKIS·디지털집현전 집계
      경로로 들어오는지 먼저 확인하는 편이 낫습니다

## 다 하고 나서 확인하는 법

1. GitHub → Actions → **인증정보 점검** → Run workflow
2. 실행 요약(Summary)에서 두 가지를 보십시오
   - `소스별 인증정보` — 값이 **주입되었는지**
   - `실제 호출 결과` — 키가 **유효한지** (`doctor --probe`)
3. 재생성된 `API_발급_연동_가이드.md` 는 그 실행의 **Artifacts** 에서 내려받습니다

> `[OK]` 는 "값이 있다"는 뜻이고, `--probe` 성공이 "키가 통한다"는 뜻입니다. 둘은 다릅니다.
