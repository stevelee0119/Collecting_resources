### 🔴 결론: 남은 실패는 **GitHub Actions IP 대역 차단**입니다

4차 실행에서 진단이 **확정**되었습니다.

```
openalex  429  [server=cloudflare cf-ray=a2fed991dad3c97f-IAD]
doaj      403  [server=cloudflare cf-ray=a2feda90d95d2ff2-IAD]
```

**두 응답 모두 Cloudflare 가, 같은 `-IAD`(워싱턴 DC) 엣지에서** 돌려준 것입니다.
Actions 러너가 그 지역에 있습니다.

이것이 결정적인 이유:

- **OpenAlex 의 429 는 OpenAlex 가 보낸 것이 아닙니다.** Cloudflare 가 보냈습니다.
  요청이 **API 에 도달조차 못 했으므로** 크레딧이 100% 그대로인 것이 설명됩니다
- `semantic_scholar` 도 이번에 **처음으로 429** 가 났습니다. 키가 정상 등록되어 있고
  `x-api-key` 헤더로 정확히 전송되는데도 막혔습니다

## 다 하고 나서 확인하는 법

1. GitHub → Actions → **인증정보 점검** → Run workflow
2. 실행 요약(Summary)에서 두 줄을 보십시오
   - `소스별 인증정보` — 값이 **주입되었는지**
   - `실제 호출 결과` — 키가 **유효한지** (`doctor --probe`)
3. 재생성된 `API_발급_연동_가이드.md` 는 그 실행의 **Artifacts** 에서 내려받습니다

> `[OK]` 는 "값이 있다"는 뜻이고, `--probe` 성공이 "키가 통한다"는 뜻입니다. **둘은 다릅니다.**
> 그리고 `--probe` 가 200 을 받아도 0건이면 C-1 의 필드명 문제입니다.
