### 🔧 원인 확정 후 코드에서 고친 것 (2차)

1. **`crossref` HTTP 400** — `select-not-available: language`
   - `select` 목록에 **Crossref 가 지원하지 않는 `language`** 가 들어 있었습니다
   - select 는 하나라도 틀리면 **요청 전체가 400** 입니다
   - → `language` 제거. 언어는 응답 본문에서 추정합니다

2. **`zenodo` HTTP 400** — `Page size cannot be greater than 25`
   - robots 예외로 **요청은 도달했고**, 이제 파라미터 문제만 남았습니다
   - 비인증 요청의 페이지 크기 상한이 **25** 인데 30 을 보내고 있었습니다
   - → 토큰이 없으면 25 로 자동 제한 (`ZENODO_API_KEY` 가 있으면 그대로 30)

3. **`core` HTTP 500** — `Could not find a property named 'createdDate'`
   - `createdDate` 는 **응답 본문에는 있지만 검색 가능한 속성이 아닙니다**
   - → 기본값을 `publishedDate` 로 바꾸고, 그래도 실패하면 **날짜 조건 없이 한 번 더
     시도**한 뒤 어느 필드를 고쳐야 하는지 경고로 남깁니다
   - 서버가 날짜를 못 거른 경우를 대비해 **수집 기간 필터를 양쪽 경계로** 강화했습니다
   - 공식 문서에서 올바른 속성명을 확인하시면 `sources.yaml` 의 `core_date_field` 에 넣으십시오

4. **`openalex` 429 진단 강화**
   - 필터를 `from_created_date` 로 바꿨는데도 429 가 유지됩니다 → **필터 문제가 아닙니다**
   - → 429 응답의 `x-ratelimit-*` · `retry-after` **헤더를 오류 메시지에 포함**시켰습니다
   - 다음 실행에서 남은 허용량이 보이면 **키 인식 문제인지 크레딧 소진인지** 갈립니다

## 다 하고 나서 확인하는 법

1. GitHub → Actions → **인증정보 점검** → Run workflow
2. 실행 요약(Summary)에서 두 줄을 보십시오
   - `소스별 인증정보` — 값이 **주입되었는지**
   - `실제 호출 결과` — 키가 **유효한지** (`doctor --probe`)
3. 재생성된 `API_발급_연동_가이드.md` 는 그 실행의 **Artifacts** 에서 내려받습니다

> `[OK]` 는 "값이 있다"는 뜻이고, `--probe` 성공이 "키가 통한다"는 뜻입니다. **둘은 다릅니다.**
> 그리고 `--probe` 가 200 을 받아도 0건이면 C-1 의 필드명 문제입니다.
